## Depth — the real limitation

| Field | Present in |
|---|---|
| `component` (identity) | 74% |
| `variants` | 70% |
| `aiHints` | 46% |
| `properties` | 37% |
| `accessibility` | 19% |
| `usage` — use cases, anti-patterns | **12%** |
| `composition` | 8% |
| `designTokens` | **6%** |

`Button` is the reference record — anti-patterns, per-state token mapping, size specs. Most records are identity plus variants.

**Consequence:** an audit of anti-patterns or token intent covers roughly a tenth of the system. Do not report such an audit as system-wide.

Note that `designTokens` at 6% no longer blocks token analysis — the [index](../index/README.md) now carries **actual** token bindings for 314 of 320 components, extracted from Figma. The metadata's `designTokens` field records *intent*; the index records *fact*. Where they disagree, that is a finding.

## Gaps are findings

Missing fields are not defects here — they are recorded and ranked in the [gaps registry](../audit/README.md). 298 components have no `usage`; the registry says which of them matter, by dependents.

```bash
python ../scripts/metadata_query.py stats
python ../scripts/metadata_query.py depth
python ../scripts/metadata_query.py gaps        # covered but missing intent fields
python ../scripts/metadata_query.py uncovered   # no metadata, ranked by usage
```

**Not covered:** BETA components (78) and Sales Journeys (7).

**36 records carry no `figmaId`** — ambiguous where the name is duplicated. Adding node ids to those records is the cheapest correctness win available.
